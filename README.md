# 实习罗盘 · AI 求职准备助手（演示原型）

面向第一次准备实习的大学生：**选目标岗位 → 填个人经历 → 模拟 AI 逐维对照岗位要求 → 输出差距分析与按优先级排序的行动清单**；支持纠正 AI 推测、行动进度回看与历史记录。

> 纯前端静态原型（HTML + CSS + 原生 JS，无框架、无后端、无数据库、无真实 AI 调用）。所有「AI 输出」由本地确定性规则引擎生成，loading、失败、延时全部本地模拟，**无任何网络请求**。

## 功能边界（考核约束：以下功能均未实现）

简历编辑 / 岗位采集与投递 / 模拟面试 / 企业招聘 / 后端服务 / 数据库 / 真实大模型 API。产品完整设计见 [product-doc.md](product-doc.md)（v1.0.2，文档规则、原型交互、模拟案例三者一致，可用 `node check.js` 验证，113 项断言）。

## 快速开始

### 方式一：Docker（评审推荐）

```bash
docker compose up --build
```

浏览器打开 **http://localhost:8080** 即可演示（首次构建约 10~30 秒）。

- 停止：`docker compose down`
- 端口冲突时：修改 `docker-compose.yml` 中 `ports` 左侧端口（如 `"8081:80"`），重启后访问对应地址

### 方式二：免安装

直接双击 `index.html`（或拖入 Chrome/Edge），全部功能本地可用，效果与 Docker 方式完全一致。

## 关键状态进入步骤（S01–S08，原型均有对应画面）

| 状态 | 进入方式 |
|---|---|
| S01 必填信息不足 | `#/form` 必填项留空（岗位/年级/专业/每周时间任一）→ 点提交 → 弹窗列缺失项，「去补充」自动定位红字字段 |
| S02 经历为空询问 | 载入案例 B（零经历）→ 提交 → 弹窗二选一 |
| S03 AI 生成失败重试 | 表单底部勾选「模拟下一次分析失败」→ 提交 → 3 秒后失败弹窗；[重试分析] 预设第二次成功；持续失败模式：URL 加 `?demo=fail-hard`（重试也失败，但始终保留「返回修改信息」出口，不死锁、输入不丢失） |
| S04 纠正 AI 推测（双向） | P04 差距表中带 [推测] 标签的行 → 点「这不准」→ **先选实际情况方向（更好/更差，必选）** + 选原因 + 填修正说明 → 提交。更好→维度上调为充足；更差→下调为缺失并生成补齐行动，纠正可升可降、不一律加分 |
| S05 建议已更新横幅 | 纠正提交后（按方向显示"已上调/已下调"文案）/ P08 标记行动完成后，右上角 toast 自动提示 |
| S06 删除确认 | P06 任意记录点「删除」 |
| S07 清空演示数据 | 顶栏「重置演示」按钮，或 URL 加 `?reset=1` |
| S08 起步模式结果页 | S02 弹窗选「确实还没有，看起步建议」→ 分析完成后的降级结果页（无匹配度，显示起步标签） |
| 修改后更新建议 | P04 →「修改信息，重新分析」→ 改目标岗位/增删经历 → 提交 → 差距表整体更新，历史保留旧记录 |
| loading 取消 | P03 点「取消分析」→ 返回表单，已填信息完整保留 |

## 评审演示脚本（五条流程均可完整演示）

### 脚本① 主流程（正常成功）

1. 首次打开（或重置后）→ **P01 空态首页**
2. 点「开始第一次差距分析」→ **P02**，点「载入案例 A · 张小雨」
3. 点「提交并生成差距分析」→ **P03 loading**（读取信息 → 对照岗位 → 生成建议）
4. 约 3 秒后 → **P04 结果页**：匹配度 **59%**，5 维度差距表（含 事实/推测 依据标签），行动清单 5 项（1 高 2 中 2 低）
5. 行动 1 点「加入我的行动」→ 顶栏「我的行动」→ **P08** 可见该行动

### 脚本② 修改与纠正流程（正向：更好）

1. 承接脚本①，P04 差距表「用户与活动运营」行（部分满足·含推测）→ 点「这不准」→ **S04 弹窗**
2. 方向选「更好：我具备相关经历/技能」，原因选「信息有误」，修正说明填「曾独立策划 300 人参与的公众号抽奖联动活动」→ 提交
3. **S05 toast** 提示已上调，该维度更新为「充足·已纠正·已上调」，匹配度 **59% → 68%**（匹配度卡显示"纠正修正：59% → 68%（↑ 上调 9 个百分点）"），行动清单移除「策划线上活动」、新增低优先级「把联动活动写成完整案例复盘」
4. 点「修改信息，重新分析」→ **P05**，目标岗位改为「数据分析实习生」→ 提交 → **P04** 差距表与行动清单整体切换为数据分析版本
5. 顶栏「我的记录」→ **P06** 可见两条记录（新旧并存）；点第一条 → **P07** 查看当时快照与纠正记录（含方向）

### 脚本③ 信息不足流程

1. `#/form` → 点「载入案例 B · 李明」（零经历）→ 提交 → **S02 弹窗**
2. 选「确实还没有，看起步建议」→ **P03** → **S08 起步模式结果页**：无匹配度、显示「起步模式」标签与 4 项起步行动包，顶部「时间偏紧，建议先聚焦前 2 项」提示（8h > 8h×80%）
3. 对比：`#/form` 必填留空直接提交 → **S01 弹窗**（阻断级信息不足，逐项定位缺失字段）

### 脚本④ AI 失败异常流程

1. `#/form` → 载入案例 A → 勾选底部「模拟下一次分析失败」→ 提交 → **P03**
2. 约 3 秒后 → **S03 失败弹窗**：「本地分析引擎未返回结果（模拟）」
3. 点「重试分析」→ loading → 成功进入 **P04**（结果与脚本①一致）
4. 备选：弹窗点「返回修改信息」→ 回 P02，全部输入保留；或 URL 加 `?demo=fail-hard` 演示持续失败（重试仍失败，出口始终存在）

### 脚本⑤ 负向纠正流程（v1.0.2 新增 · 评审反例：纠正"不会 Excel、没有 SQL 经验"）

1. 重置演示 → `#/form` → 载入案例 A → 提交 → **P04**（匹配度 59%）
2. 差距表「数据分析与工具」行（部分满足·含推测"推测缺乏数据工具实操"）→ 点「这不准」→ **S04 弹窗**
3. 方向选「更差：我其实不具备或更弱」，原因选「信息有误」，修正说明填「我不会 Excel，也没有 SQL 经验」→ 提交
4. **负向修正生效**：该维度**下调为「缺失」**、标签「已纠正·已下调」；匹配度 **59% → 45%**（匹配度卡红色对比条"纠正修正：59% → 45%（↓ 下调 14 个百分点）"）；行动清单替换为高优先级「完成 Excel 与 SQL 基础课程」+「用课程或社团数据做 1 次完整分析练习」共 6 项；**S05 toast** 提示"已按你的纠正下调该维度并更新补齐行动"
5. **行动验证闭环**：把「完成 Excel 与 SQL 基础课程」加入行动 → **P08** 标记完成 → 回 P04「查看最新建议」→ 该维度回升「部分满足·已提升」、匹配度回到 **59%**——负向纠正不加分，差距由行动补齐
6. 顶栏「我的记录」→ **P07** 纠正记录显示方向「实际情况更差（下调为缺失）」

## 恢复初始状态

任选其一：

1. 页面右上角「重置演示」→ 确认弹窗（S07）→ 回到首次打开空态
2. URL 加 `?reset=1`（如 `http://localhost:8080/?reset=1`）
3. 清除浏览器站点数据（原型数据存于 localStorage，与 Docker 容器无关，`docker compose down` 不会清除）
